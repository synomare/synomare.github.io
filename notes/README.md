# Notes（ブログ）の運用メモ

`notes/` 以下は Markdown 原稿から記事 HTML と一覧データを生成する簡易な仕組みです。
公開ページ生成は `scripts/new-post.mjs`、専用エディターは React・Vite・CodeMirror が担当します。

## Notes専用エディター（文章を書くときはこちら）

1. `https://synomare.github.io/admin/notes/` を直接開き、**LOGIN WITH GITHUB**を押します。
2. ログイン直後は **OPEN A NOTE** 入口が表示されます。ここで過去記事の一覧から編集する記事を選ぶか、**＋ NEW NOTE** で新規記事を始めます。最初から最新記事を自動で開くことはありません。
3. 編集中に **LIBRARY**を開くと、公開済み・下書きを大きく見やすい一覧で確認できます。タイトル／本文／slug／タグの検索、TEXT／PHOTO・公開状態・タグでの絞り込み、日付／タイトル順の並べ替えに対応しています。記事を押すと、そのまま同じエディターで過去記事を編集できます。
4. 新規投稿は **＋ NEW NOTE**、過去記事を元に作る場合は **DUPLICATE** を使います。複製は新しいslugと日付を持つGitHub下書きになるため、内容とタイトル末尾の「— copy」を確認してから公開します。TEXTはタイトルと本文、PHOTOは写真1枚だけで公開できます。slug・日付・概要・タグは自動補完されます。
5. 本文中で `[[` と入力すると既存記事が候補に出ます。`[[記事名]]` または `[[記事名|表示名]]` で記事同士をつなげられます。
6. **DETAILS** ではカードサイズAUTO/S/M/L、概要、カード用抜粋、タグ、別名、公開状態を変更できます。タグと別名は複数登録でき、入力欄へカンマ区切りで貼り付けるか、Enter／カンマ／「、」／**ADD**で追加します。チップの×で個別に外せます。AUTOではPHOTOをL、画像入りTEXTをM、画像なしTEXTをSとして配置し、S/M/Lを選んだ場合はその指定を優先します。
7. TEXTで **＋ IMAGE** を使うと、従来どおり本文へ何枚でも画像を挿入できます。PHOTOでは1枚だけを選び、もう一度選ぶと公開待ちの写真を置き換えます。HEICはJPEG、SVGや大きな静止画はWeb表示向けのWebPへ自動変換され、画像はMarkdownと同じGitコミットで `assets/images/notes/` へ保存されます。元のファイル名は記事には表示されません。
8. **PUBLISH** または `Ctrl/Cmd + Enter` で公開します。公開中はGitHub画面を開く必要はありません。

### 執筆支援機能

- 本文上のツールバーからH2／H3、太字、通常リンク、`[[内部リンク]]`、引用、箇条書き、番号リスト、タスク、コード、区切り線、Undo／Redoを挿入できます。選択中の文字がある場合はその文字へ書式を適用します。
- Cosenseのように行単位で階層を調整できます。行または複数行を選び、`DEPTH +`／`DEPTH −`、または `Tab`／`Shift + Tab`（`Ctrl/Cmd + ]`／`[`）を使います。箇条書きは入れ子リスト、引用は入れ子引用、見出しは `#` の数としてMarkdownへ保存されるため、公開ページでも同じ階層が再現されます。`LEVEL +`／`LEVEL −`は見出しだけの深度を調整します。本文下の `BLOCK DEPTH` でカーソル行の現在値を確認できます。
- 箇条書き・番号リスト・引用の行でEnterを押すと同じ階層を継承し、空の項目でもう一度Enterを押すとその階層を抜けます。通常の段落を深くするときは、4スペースのコードブロックにならないよう自動的に入れ子引用へ切り替わります。
- **EDIT／SPLIT／PREVIEW**で編集のみ、編集とプレビューの左右表示、プレビューのみを切り替えます。プレビューではMarkdownと内部リンクの見え方を公開前に確認できます。
- **FOCUS**は上部メニューと右側Inspectorを隠します。`Esc`で通常表示へ戻ります。
- 右側の**OUTLINE**からタイトルや見出し位置へ移動できます。本文下には空白を除く文字数、概算読了時間、見出し数、自動保存状態が表示されます。
- 画像は**＋ IMAGE**に加え、本文への貼り付けとドラッグ＆ドロップでも追加できます。公開待ち画像の`×`を押すと、アップロードと本文の画像記法をまとめて取り消します。
- **PUBLISH CHECK**はタイトル／本文／写真／slug／日付／重複タイトル／未解決内部リンクを確認します。赤いエラーがある間は公開できず、未解決リンクなどの警告は確認したうえで公開できます。
- **COPY MD**でfrontmatterを含むMarkdown全体をコピーできます。書式のショートカットは`Ctrl/Cmd + B`、通常リンクは`Ctrl/Cmd + K`、内部リンクは`Ctrl/Cmd + Shift + K`、公開は`Ctrl/Cmd + Enter`です。

### 記事運用ツール（TOOLS）

- **TAGS**ではタグの使用件数・公開／下書き内訳・使用記事を確認できます。**RENAME**で表記をまとめ、**SAVE TAG CHANGES**を押すと複数記事を1コミットで更新します。保存前なら**DISCARD**で戻せます。
- **MEDIA**では本文やPHOTOで使われている画像を一覧し、使用記事を開く、パスをコピーする、現在の記事へ再利用する操作ができます。画像ファイルの削除は行いません。
- **LINKS**では`UNRESOLVED`（未解決）、`AMBIGUOUS`（同名・同aliasで曖昧）、`ORPHAN`（リンクのない孤立記事）を検出します。行の**OPEN**からリンク元／対象記事を開き、slug・タイトル・aliasを修正してください。

入力内容は約0.5秒後にブラウザ内へ自動保存されます。GitHubログインのtokenはメモリだけに保持され、IndexedDB・localStorage・リポジトリには保存されません。別の更新によってmainが進んだ場合は上書きせず **CONFLICT** と表示するため、**RELOAD**後に差分を確認して再度公開してください。

iPhoneでは **LIBRARY** と **TOOLS** が全画面で開きます。LIBRARYの検索・絞り込みから過去記事を選び、TOOLSのタグ・画像・リンク保守へ切り替えられます。上部の記事選択でも既存記事／**＋ NEW NOTE**を素早く切り替えられます。画面下の **＋ IMAGE**、**DETAILS**、**COPY MD**、**PUBLISH** から主要操作を行います。書式ツールバーは横へスクロールでき、EDIT／SPLIT／PREVIEWも同じ列から切り替えられます。**DETAILS**は本文の上に開くため、閉じるとすぐ執筆へ戻れます。アウトライン・リンク・バックリンク・関連記事は本文下の **DOCUMENT / CONNECTIONS** を開いたときだけ表示されます。下部操作はセーフエリアを避けて固定され、入力内容はPCと同じく自動退避されます。

画像はJPEG・PNG・WebP・GIF・AVIF・BMP・SVG・HEIC／HEIFに対応します。1ファイル40MBまで選択でき、変換後が15MBを超える場合や、画像として読み取れない場合は公開前にエラーになります。HEICをそのまま含む既存記事やDecap CMSからの投稿は、公開ビルドでもJPEGへ変換されます。外部画像が後から削除された場合など、ブラウザで読み込めなかった画像には本文内の代替パネルと元ファイルへのリンクが表示され、一覧カードにも欠損表示が残ります。

記事の削除、壊れたfrontmatterの修復、従来画面での復旧は `https://synomare.github.io/admin/` を使用します。専用エディターには誤操作防止のため削除機能を置いていません。

公開Notes一覧では、写真単体を画像主体の大きなブロック、テキストを小さな読み物として自動配置します。`card_size: s | m | l`を明示すると自動判定より優先され、閲覧者側のVIEW S/M/Lとも同時に反映されます。PHOTOの詳細は写真と最小限の日時・前後移動だけを表示し、TEXTの記事ページには内部リンク、バックリンク、共有タグによる関連記事、ローカルグラフが表示されます。

Notes一覧と記事内の前後移動は公開日が新しい順です。同じ公開日の記事は、専用エディターが付けるJSTタイムスタンプslugの新しい順（上が最新）になります。

公開ページの大きな英字ディスプレイには `OTTO ATTACTYPE` を使い、日本語本文はZen Old Mincho、日付・タグ・操作UIはSpace Monoを維持します。OTTOのWeb利用許諾はZIP内で確認できていないため、購入元の条件を確認してから公開反映してください。

## 管理画面から更新する（通常はこちら）

1. `https://synomare.github.io/admin/` を直接開きます。公開サイト上には管理画面へのリンクを置いていません。
2. **Login with GitHub** を選び、`synomare/synomare.github.io` へ push できる GitHub アカウントでログインします。
3. **Notes → New Note** から投稿タイプを選びます。テキスト投稿はタイトルと本文、写真投稿は「写真投稿の画像」を入力します。
   - slug は英小文字・数字・ハイフンだけを使用します。公開URLになるため、公開後は変更しません。
   - 本文内の画像ボタンからアップロードした画像は `assets/images/notes/` に保存されます。
   - 編集画面の Preview で本文の見え方を確認できます。
   - すぐ公開しない場合は「公開設定」の下書きをオンにして保存します。下書きは保存されますが公開一覧には出ません。
4. 下書きを公開するときは「公開設定」の下書きをオフにして **Publish** を押します。Markdown と画像が `main` へ保存され、GitHub Actions が記事HTMLと一覧を自動生成します。
5. 数分後に `https://synomare.github.io/notes/` と記事URLを確認します。

記事を削除するときは、管理画面で対象記事を開き、上部（画面幅によってはメニュー内）の **Delete** を選んで確認します。確認すると削除コミットが作成され、Markdownと生成済み記事HTMLが取り除かれて数分後に一覧からも消えます。下書き承認・予約公開は使わず、下書きフラグで安全に公開前確認を行います。

Notes一覧では、タイトル・概要・タグの全文検索、タグ・年の絞り込み、URL共有に対応しています。検索条件を残したURLをブックマークや共有に使えます。

## Worksを管理画面から更新する

1. 管理画面の **Works → New Work** を開きます。
2. slug、作品名、制作年、説明、種別を入力します。
3. 必要に応じてリンク先、一覧画像、表示優先度を設定します。
   - 一覧画像は10MBまで選択できます。大きすぎる画像はアップロード前に縮小してください。
4. すぐ公開しない場合は「公開設定」の下書きをオンにして保存します。公開するときはオフにして **Publish** を押します。
5. **Publish** を押すと `works.html` が自動生成され、数分後に公開されます。
6. 削除するときは対象作品を開き、上部の **Delete** を選びます。

既存作品「嶼群（博物館（たち））」もWorksコレクションへ移行済みです。一覧画像を設定した作品だけ画像付きの行になり、未設定の場合は従来どおりテキスト行で表示されます。

Works一覧では、作品名・説明・種別の全文検索、種別・年の絞り込み、URL共有に対応しています。

### 公開に失敗した場合

- GitHub Actions の `Build and deploy GitHub Pages` が失敗した場合、公開中のサイトは直前の成功版のまま維持されます。
- 原稿の修正は管理画面から行い、再度 Publish します。
- 誤った更新を戻す必要がある場合は、GitHub のコミット履歴から該当ファイルを復元します。OAuth ID、secret、アクセストークンはリポジトリへ保存しません。

## 記事を新規作成する
1. ターミナルでリポジトリ直下に移動します。
2. 次のコマンドで記事を生成します。
   ```
   node scripts/new-post.mjs slug "タイトル" --date=YYYY-MM-DD --summary="概要文" --tags=タグ1,タグ2
   ```
   - `slug` は英小文字・数字・ハイフンのみ。URL は `notes/<slug>.html` になります。
   - `--date` を省略すると当日の日付が入ります。
   - `--summary` は一覧やメタ情報に使われる 1〜2 文です。
   - `--tags` はカンマ区切り、または複数回の `--tag` 指定で追加できます。
3. スクリプトが自動で以下を生成・更新します。
   - `notes/content/<slug>.md`: フロントマター付き Markdown 原稿
   - `notes/posts.json`: 投稿メタデータ（ソート済み）
   - `notes/posts.js`: フロント側で読み込む派生データ
   - `notes/<slug>.html`: テンプレートを元にした記事 HTML
4. 生成された Markdown を編集し、本文やメタ情報を整えます。
5. 編集後は `node scripts/new-post.mjs --rebuild` を実行し、HTML と `posts.js` を最新化します。

## 既存記事の編集
- 通常は管理画面から編集します。ローカル作業が必要な場合は `notes/content/<slug>.md` を編集します。
- 編集後に `node scripts/new-post.mjs --rebuild` を実行すると、HTML と一覧データが最新状態になります。

## 再生成のみ行うとき
- Markdown のみ更新した場合は、次のコマンドで一括再生成できます。
  ```
  node scripts/new-post.mjs --rebuild
  ```

## 検証

```text
npm test
npm run check
```

- `npm test` は一時フォルダ内のfixtureでHTML生成、記事順、画像、YouTube/X埋め込み、不正slug、必須項目、壊れたfrontmatterを検証します。
- `npm run check` は公開原稿とWorks原稿を変更せず、現在のコンテンツ全体を検証します。

## Markdown の埋め込み記法
- 段落中に YouTube のリンク（`youtube.com/watch?v=...` または `youtu.be/...`）だけを置くと、`--rebuild` 時に自動でプレイヤーの iframe に変換されます。
- 同様に X / Twitter のステータス URL だけの段落は埋め込みブロックに変換されます。
- 記事内の最初の画像はサムネイル（`image`）として `posts.json` / `posts.js` に記録されます。

## 参考
- 投稿テンプレートは `notes/post-template.html` にまとまっています。スタイルや構造を変えたいときはテンプレートを編集してから再生成してください。
- `notes/posts.js` にはタグ配列のほか `year` や `yearMonth` などの派生プロパティが含まれているため、アーカイブやフィルタ機能を実装する際に利用できます。
