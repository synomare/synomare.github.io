# Notes（ブログ）の運用メモ

`notes/` 以下は Markdown 原稿から記事 HTML と一覧データを生成する簡易な仕組みです。
公開ページ生成は `scripts/new-post.mjs`、専用エディターは React・Vite・CodeMirror が担当します。

## Notes専用エディター（文章を書くときはこちら）

1. `https://synomare.github.io/admin/notes/` を直接開き、**LOGIN WITH GITHUB**を押します。
2. ログイン直後は **OPEN A NOTE** 入口が表示されます。ここで過去記事の一覧から編集する記事を選ぶか、**＋ TEXT**／**＋ PHOTO** で投稿形式を決めて新規記事を始めます。最初から最新記事を自動で開くことはありません。
   - iPhoneでは記事一覧を初期画面へ早く出すため、TYPE／STATUS／TAG／SORTを **FILTERS** の中へ折り畳みます。必要なときだけ開き、絞り込んだ後は閉じても `1 ACTIVE` などの件数が残ります。デスクトップでは4項目を常時表示します。
   - 通常回線では入口画面の空き時間に本文エディターを先読みし、記事選択後の待ちを短くします。データセーバーまたは2G相当では自動先読みせず、記事・新規作成・端末下書きを選ぶ直前だけ読み込みを始めます。画像変換機能は画像を選ぶまで読み込みません。
   - 通信の瞬断などで本文エディターを読み込めなかった場合も、画面全体は閉じず本文領域に **EDITOR UNAVAILABLE** を表示します。通信状態を確認して **RETRY EDITOR** を押すと、その場で取得をやり直せます。タイトルやLOCAL DRAFTSはこの操作では削除されません。
   - **SPLIT**／**PREVIEW**は、ボタンへ触れるかキーボードfocusが入った時点で公開前プレビューを先読みします。取得に失敗しても本文編集は維持され、**PREVIEW UNAVAILABLE**内の **RETRY PREVIEW** からプレビューだけを再取得できます。
3. 編集中に **LIBRARY**を開くと、公開済み・下書きを大きく見やすい一覧で確認できます。タイトル／本文／slug／タグの検索、TEXT／PHOTO・公開状態・タグでの絞り込み、日付／タイトル順の並べ替えに対応しています。記事を押すと、そのまま同じエディターで過去記事を編集できます。
4. 新規TEXTは **＋ TEXT**、写真単体は **＋ PHOTO**、過去記事を元に作る場合は **DUPLICATE** を使います。PHOTOを選ぶと本文エディターを経由せず写真専用画面へ入ります。複製は新しいslugと日付を持つGitHub下書きになるため、内容とタイトル末尾の「— copy」を確認してから公開します。TEXTはタイトルと本文、PHOTOは写真1枚だけで公開できます。slug・日付・概要・タグは自動補完されます。
5. 本文中で `[[` と入力すると既存記事が候補に出ます。`[[記事名]]` または `[[記事名|表示名]]` で記事同士をつなげられます。
6. **DETAILS** ではカードサイズAUTO/S/M/L、概要、カード用抜粋、タグ、別名、公開状態を変更できます。タグと別名は複数登録でき、入力欄へカンマ区切りで貼り付けるか、Enter／カンマ／「、」／**ADD**で追加します。チップの×で個別に外せます。**RELATED NOTES**では関連記事を検索して任意に**ADD**／**REMOVE**できます。タグからの自動候補にはAUTO、手動指定にはMANUALが表示され、REMOVEした記事はタグが共通していても自動で戻りません。EXCLUDEDの**RESTORE**で自動候補へ戻せます。AUTOではPHOTOをL、画像入りTEXTをM、画像なしTEXTをSとして配置します。画像入りTEXTはVIEW S/M/Lの各密度で長文TEXTと同程度の横幅に抑え、サムネイルだけが過度に大きくならないようにします。S/M/Lを明示した場合はAUTO調整よりその指定を優先します。
7. TEXTで **＋ IMAGE** を使うと、従来どおり本文へ何枚でも画像を挿入できます。PHOTOでは1枚だけを選び、もう一度選ぶと公開待ちの写真を置き換えます。写真プレビューにはタイトル、説明、日付の順で代替テキストを付け、iPhoneでは縦長写真を画面内で確認できる高さに抑えます。既存画像が取得できない場合は **PHOTO UNAVAILABLE** と再選択案内へ切り替わります。HEICはJPEG、SVGや大きな静止画はWeb表示向けのWebPへ自動変換され、画像はMarkdownと同じGitコミットで `assets/images/notes/` へ保存されます。元のファイル名は記事には表示されません。本文エディターでは長い画像パスを通常時は **IMAGE 01 / EDIT MARKDOWN** のような小さなブロックへ畳み、クリック、Enter、Spaceで元のMarkdownを開いて編集できます。別の文章へカーソルを移すと再び畳まれます。この表示切替だけでは本文や端末下書きは変更されません。画像の直後に空行を入れず文章を書いた場合も、公開生成時に画像を広い独立ブロック、文章を通常の読み幅の段落へ分離します。
8. **PUBLISH** または `Ctrl/Cmd + Enter` で公開キューへ追加します。追加が済んだら、そのコミットの完了を待たずに別の記事へ切り替え、続けてPUBLISHできます。GitHub画面を開く必要はありません。

### 連続公開とPUBLICATION QUEUE

- PUBLISHを押した時点の本文・メタデータ・未送信画像を固定したスナップショットとして、画面内の **PUBLICATION QUEUE** へ追加します。キューは上から1件ずつ処理し、1件目で作られたcommit SHAを2件目の親、2件目を3件目の親にするため、短時間に連続公開してもmainへのpushが衝突しません。
- 処理中または停止中は固定操作列に現在位置と待機数を表示します。全件完了後は固定QUEUEを自動的に片付けて本文領域を戻し、折り畳まれた **PUBLICATION QUEUE / COMPLETE** の履歴だけを残します。履歴は内容を確認してからCLEARできます。
- まだ **WAITING** の項目は **KEEP DRAFT** で個別にキューから外せます。処理中・停止中・完了済みの項目は外せません。Markdownと未送信画像はLOCAL DRAFTSへ残るため、そのまま編集して再度PUBLISHできます。
- 編集中は画面下の **QUEUE** に、処理中の位置、全件数、待機数が常に表示されます。iPhoneでは原稿の一時通知を省いて、キューとローカル下書き状態だけを表示します。QUEUEを押すと詳細一覧へ移動し、現在処理中の記事と後続の順番を確認できます。
- 処理中も別の記事の編集、ローカル自動保存、次の記事のキュー追加を続けられます。同じslugを重ねて追加することだけは止め、最初の項目が完了してから次の更新を追加します。キュー実行中はmainの基準が変わる **RELOAD**、**LOG OUT**、タグ一括保存を一時的に無効化します。
- 通信失敗や外部の更新とのCONFLICTが起きると、その項目でキュー全体を停止し、後続を勝手に処理しません。一時的な通信失敗なら **RETRY**、競合を整理する場合は **STOP & KEEP DRAFTS** を押します。後者は未完了の順番待ちだけを解除し、原稿と画像はLOCAL DRAFTSに残すので、RELOAD後に内容を確認して再度PUBLISHできます。
- OAuth tokenは従来どおりメモリだけに保持します。公開キュー自体もその画面を開いている間だけ動作し、ページを閉じたり再読み込みした場合に自動再送はしません。終了前にはブラウザが警告し、未完了原稿はIndexedDBのLOCAL DRAFTSから再開できます。これにより、復帰時に意図しない二重commitを作りません。

### 執筆支援機能

- 本文の行頭で `/` を入力すると、見出し（`/h2`・`/h3`）、箇条書き（`/bullet`）、番号リスト（`/number`）、タスク（`/task`）、引用（`/quote`）、コード（`/code`）、区切り線（`/divider`）、内部リンク（`/wikilink`）をキーボードから選べます。候補名の途中まで入力して絞り込み、Enterで確定します。日本語IMEの変換中には候補確定を割り込ませません。
- 本文上のツールバーからH2／H3、太字、通常リンク、`[[内部リンク]]`、引用、箇条書き、番号リスト、タスク、コード、区切り線、Undo／Redoを挿入できます。選択中の文字がある場合はその文字へ書式を適用します。
- **FIND**または`Ctrl/Cmd + F`で、エディター内の検索・置換パネルを開きます。前後の一致へ移動、全一致の選択、大文字小文字・正規表現・単語単位の指定、1件ずつの置換、すべて置換に対応します。検索結果は本文上で赤く強調され、置換内容も通常の本文編集と同じくUndo／自動保存／公開差分へ反映されます。`Esc`または×で閉じます。
- Cosenseのように行単位で階層を調整できます。行または複数行を選び、`DEPTH +`／`DEPTH −`、または `Tab`／`Shift + Tab`（`Ctrl/Cmd + ]`／`[`）を使います。箇条書きは入れ子リスト、引用は入れ子引用、見出しは `#` の数としてMarkdownへ保存されるため、公開ページでも同じ階層が再現されます。`LEVEL +`／`LEVEL −`は見出しだけの深度を調整します。本文下の `BLOCK DEPTH` でカーソル行の現在値を確認できます。
- 箇条書き・番号リスト・引用の行でEnterを押すと同じ階層を継承し、空の項目でもう一度Enterを押すとその階層を抜けます。通常の段落を深くするときは、4スペースのコードブロックにならないよう自動的に入れ子引用へ切り替わります。
- **EDIT／SPLIT／PREVIEW**で編集のみ、編集とプレビューの左右表示、プレビューのみを切り替えます。プレビューではMarkdownと内部リンクの見え方を公開前に確認できます。
- **FOCUS**は上部メニューと右側Inspectorを隠します。`Esc`で通常表示へ戻ります。
- 右側の**OUTLINE**からタイトルや見出し位置へ移動できます。本文下には空白を除く文字数、概算読了時間、見出し数、自動保存状態が表示されます。
- 画像は**＋ IMAGE**に加え、本文への貼り付けとドラッグ＆ドロップでも追加できます。公開待ち画像の`×`を押すと、アップロードと本文の画像記法をまとめて取り消します。
- **PUBLISH CHECK**はタイトル／本文／写真／slug／日付／重複タイトル／未解決内部リンクを確認します。赤いエラーがある間は公開できず、未解決リンクなどの警告は確認したうえで公開できます。
- **CHANGES FROM GITHUB**では、通常の編集でも読み込み時のGitHub版と現在の原稿を比較できます。閉じた状態で変更フィールド数と本文の追加／削除行数を確認でき、開くとタイトル、日付、概要、タグ、別名、関連記事、カード設定、公開状態、写真と本文行の差分が表示されます。変更なしは**NO CHANGES**、新規原稿は**NEW NOTE**になります。比較は表示専用で、原稿やGitHub版を自動的に書き換えません。
- **COPY MD**でfrontmatterを含むMarkdown全体をコピーできます。本文検索は`Ctrl/Cmd + F`、太字は`Ctrl/Cmd + B`、通常リンクは`Ctrl/Cmd + K`、内部リンクは`Ctrl/Cmd + Shift + K`、公開は`Ctrl/Cmd + Enter`です。

#### 公開ページでの階層表示

エディターの階層は公開記事でもCosenseのようなブロックの入れ子として表示されます。1段目の通常テキストは先頭2スペース、2段目以降は `  > 子ブロック`、`  > > 孫ブロック` のようにMarkdownへ保存され、生成HTMLではそれぞれ `.note-block.note-depth-1`、`.note-depth-2` などのブロックになります。公開ページ側では深度に応じて余白とガイド線が増えるため、隣り合う文章の親子関係をそのまま辿れます。見出し、箇条書き、通常の引用、コードブロックはMarkdown本来の構造を維持し、通常の引用（`> 引用`）はテキスト階層とは別の赤い引用線で表示されます。

深度付きの行は隣の段落に吸収されず、1行ずつ独立したブロックとして生成されます。深度付き行に画像やYouTube／Xの単独リンクを置いた場合も、通常の本文と同じ画像エラー表示・埋め込み処理が適用されます。

### 記事運用ツール（TOOLS）

- **TAGS**ではタグの使用件数・公開／下書き内訳・使用記事を確認できます。**RENAME**で表記をまとめ、**SAVE TAG CHANGES**を押すと複数記事を1コミットで更新します。保存前なら**DISCARD**で戻せます。変更待ちの間は別記事への切替・複製・RELOAD・LOG OUTを止めるため、必ずSAVEかDISCARDを選んでから次の操作へ進みます。競合した場合も変更内容は画面内に残るので、DISCARD後にRELOADして最新版へ同じ変更をやり直してください。
- **MEDIA**では本文やPHOTOで使われている画像を一覧し、使用記事を開く、パスをコピーする、現在の記事へ再利用する操作ができます。画像ファイルの削除は行いません。
- **LINKS**では`UNRESOLVED`（未解決）、`AMBIGUOUS`（同名・同aliasで曖昧）、`ORPHAN`（リンクのない孤立記事）を検出します。行の**OPEN**からリンク元／対象記事を開き、slug・タイトル・aliasを修正してください。

### ローカル下書きの再開と破棄

- 未公開の原稿と未送信画像は、約0.5秒後にこの端末のIndexedDBへ保存されます。ブラウザを閉じた後も、次回GitHubログイン後の **OPEN A NOTE** に **LOCAL DRAFTS** として現れ、**RESUME**から続けられます。
- 新規原稿の保存IDはslugとは別に固定されるため、DETAILSでslugを何度変更しても下書きが増殖しません。旧版で保存された`note:new`形式も自動削除せず、同じ一覧から再開できます。
- 既存記事を端末で編集した場合は、過去記事の同じ行へ **LOCAL CHANGES** としてまとめて表示します。同じ記事を複数タブで編集した場合は、古い方も **PARALLEL EDIT** としてLOCAL DRAFTSへ残すため、別タブの原稿で黙って上書きしません。GitHubから削除された元記事は **REMOTE MISSING**、新規下書きのslugがGitHub記事と重なった場合は **SLUG CONFLICT** と表示し、意図しない上書きを止めます。
- **DISCARD**は、この端末だけにある本文と未送信画像を破棄します。確認画面では **KEEP DRAFT** が最初に選ばれ、確定してもGitHub上の記事は削除・変更されません。公開に成功した場合だけ、対応するローカル下書きが自動で消えます。通信失敗やCONFLICTでは残るため、そのまま再試行できます。
- ローカル下書きは同じブラウザ・同じ端末だけの退避です。Private Browsing、ブラウザのサイトデータ削除、OSによるストレージ消去では失われる可能性があります。画面が `LOCAL CHANGES` の間にアプリを強制終了せず、`LOCAL DRAFT SAVED`を確認してください。

入力内容は約0.5秒後にブラウザ内へ自動保存されます。画面下では公開・画像・コピーなどの操作結果と `LOCAL CHANGES`／`LOCAL DRAFT SAVED` の退避状態を別々に表示するため、ERRORやCONFLICTが自動保存表示で消えることはありません。画像変換・タグ一括保存と、公開キューへスナップショットを追加する短い間だけ本文操作を止めます。GitHubへのコミット処理はバックグラウンドで1件ずつ進み、その間も別の記事へ切り替えて編集できます。GitHubログインのtokenはメモリだけに保持され、IndexedDB・localStorage・リポジトリには保存されません。別の更新によってmainが進んだ場合は上書きせず **CONFLICT** と表示します。PUBLICATION QUEUEを停止してRELOADし、比較画面で本文に加えてタイトル・日付・概要・タグ・別名・関連記事・カード設定・公開状態のGitHub版／ローカル版を確認します。ローカル原稿を採用する場合だけ **差分を確認し、ローカル原稿を採用する** を押してから再度公開してください。

iPhoneでは **LIBRARY** と **TOOLS** が全画面で開きます。LIBRARYの検索・絞り込みから過去記事を選び、TOOLSのタグ・画像・リンク保守へ切り替えられます。上部の記事選択でも既存記事／**＋ NEW TEXT**／**＋ NEW PHOTO**を素早く切り替えられます。画面下の **＋ IMAGE**、**DETAILS**、**COPY MD**、**PUBLISH** から主要操作を行います。通常はEDIT／SPLIT／PREVIEW／FOCUSだけを一列で表示し、**FORMAT**を押したときだけ横スクロール式の書式列を開きます。書式を1つ適用すると自動的に閉じるため、本文領域を広く保てます。**FOCUS**ではサイトヘッダー、投稿タイプ、日付などを隠し、現在の記事タイトルだけを一行の細いバーへ残して本文領域を広げます。もう一度FOCUSを押すと、タイトルやメタデータを含む通常編集へ戻ります。**DETAILS**は本文の上に開くため、閉じるとすぐ執筆へ戻れます。アウトライン・リンク・バックリンク・関連記事は本文下の **DOCUMENT / CONNECTIONS** を開いたときだけ表示されます。下部操作はセーフエリアを避けて固定され、入力内容はPCと同じく自動退避されます。

画像はJPEG・PNG・WebP・GIF・AVIF・BMP・SVG・HEIC／HEIFに対応します。1ファイル40MBまで選択でき、変換後が15MBを超える場合や、画像として読み取れない場合は公開前にエラーになります。HEICをそのまま含む既存記事やDecap CMSからの投稿は、公開ビルドでもJPEGへ変換されます。外部画像が後から削除された場合など、ブラウザで読み込めなかった画像には本文内の代替パネルと元ファイルへのリンクが表示され、一覧カードにも欠損表示が残ります。

記事の削除、壊れたfrontmatterの修復、従来画面での復旧は `https://synomare.github.io/admin/` を使用します。専用エディターには誤操作防止のため削除機能を置いていません。

公開Notes一覧では、画像のないテキストを小、画像を含むテキストを中、写真単体を大として自動配置します。AUTOのテキストはタイトルと抜粋の長さも見て、短い断片をさらに細く、長い文章を少し広くします。サムネイル付き記事だけが過度に大きくならないよう横幅と画像比率を抑え、テキストだけの記事との視覚量を近づけています。デスクトップでは公開順を維持したまま12列の空きを詰め、カードが単純な等幅格子に見えないよう画像量・文章量に応じたまとまりを作ります。最後に1件だけ残ったカードは、最短で置ける位置を基準に、縦差48px以内の候補から中央に最も近い空きを選びます。前段に大きな空きがあるのに、必ず下段中央へ落とすことはありません。画像読込やWebfontでカード高さが変わった場合はResizeObserverで再計算します。iPhoneでは大見出しと説明を横に組み、検索と最新記事へ早く到達できる構成に切り替わります。各カードの `N.001`／`P.001` は公開時の最新順を表し、検索・タグ・年で絞り込んでも番号は変わりません。**FILTERS**には有効な絞り込み数とVIEW S/M/Lが表示され、デスクトップでは一覧の上へ重ね、iPhoneでは一覧を押し下げて開きます。外側のクリック／タップまたはEscapeで閉じられ、Escapeでは操作位置がFILTERSへ戻ります。**CLEAR FILTERS**は検索・タグ・年だけを解除してVIEW S/M/Lの好みを維持し、パネルを閉じて検索欄へ戻ります。`card_size: s | m | l`を明示すると自動判定より優先され、閲覧者側のVIEW S/M/Lとも同時に反映されます。PHOTOの詳細は写真と最小限の日時・前後移動だけを表示します。TEXTの記事ページはノードグラフを表示せず、記事全体を最大1180pxの一列で使います。文章は読みやすい約48emに収めて中央へ置き、画像や動画はその外側まで広く表示します。内部リンク、バックリンク、関連記事は存在する項目だけを本文下へ続けます。記事ヘッダーには日付と固定番号（例：`N.003 / TEXT`）を左右へ配置し、一覧から詳細へ移ってもアーカイブ上の位置が分かります。記事末尾は **ARCHIVE / ALL NOTES**、**← NEWER**、**OLDER →** の位置を固定し、各記事タイトルを別の行で表示します。モバイルでは一覧を上段、新しい／古い記事を左右の下段へ並べるため、長いタイトルでも方向を見失いません。上部のサイトナビゲーションは横一列のまま、各リンクを44px以上のタップ領域にして必要な場合は横スクロールできます。関連記事はタグ共有が基本ですが、frontmatterの`related_notes`でslug／タイトル／aliasを指定した記事を手動追加し、`related_exclude`で自動候補から除外できます。手動追加はタグが共通しない記事にも適用され、`related_notes`に書いた順番がそのまま公開順になります。エディターの↑↓で手動関連記事の順番を変更でき、RESET AUTOで手動追加・除外を一度に解除できます（変更はまずローカル下書きへ保存され、公開ボタンを押すまでGitHubへ送信されません）。未解決・曖昧・自分自身・下書きのみの参照、追加と除外の重複は警告として表示され、公開自体は止まりません。曖昧な参照には候補ごとのREPAIR、不要な参照にはREMOVEがあります。自動候補は公開済み記事だけから最大6件まで補完し、検索では下書きを含む全記事を確認できます。

PHOTOの詳細は日付と固定番号（例：`P.002 / PHOTO`）、写真、前後移動だけへ絞ります。無題でも読み上げ用見出しと自動代替テキストを生成し、デスクトップでは縦長写真を画面高の82%以内に収めて全体像を保ちます。タイトルまたは手動概要がある場合だけ写真下の説明として表示し、ファイル名は表示しません。画像が取得できない場合は、代替パネルと元画像を開くリンクへ切り替わります。

Notes一覧と記事内の前後移動は公開日が新しい順です。同じ公開日の記事は、専用エディターが付けるJSTタイムスタンプslugの新しい順（上が最新）になります。

公開ページの大きな英字ディスプレイには `OTTO ATTACTYPE` を使い、日本語本文はZen Old Mincho、日付・タグ・操作UIはSpace Monoを維持します。OTTOのWeb利用許諾はZIP内で確認できていないため、購入元の条件を確認してから公開反映してください。

## 管理画面から更新する（通常はこちら）

1. `https://synomare.github.io/admin/` を直接開きます。公開サイト上には管理画面へのリンクを置いていません。
2. **Login with GitHub** を選び、`synomare/synomare.github.io` へ push できる GitHub アカウントでログインします。
3. **Notes → New Note** から投稿タイプを選びます。テキスト投稿はタイトルと本文、写真投稿は「写真投稿の画像」を入力します。
   - slug は英小文字・数字・ハイフンだけを使用します。公開URLになるため、公開後は変更しません。
   - 本文内の画像ボタンからアップロードした画像は `assets/images/notes/` に保存されます。
   - 編集画面の Preview で本文の見え方を確認できます。
   - すぐ公開しない場合は「公開設定」の下書きをオンにして保存します。下書きは保存されますが公開一覧には出ません。
4. 下書きを公開するときは「公開設定」の下書きをオフにして **Publish** を押します。Markdown と画像が `main` へ保存され、GitHub Actions が記事HTMLと一覧を自動生成します。
5. 数分後に `https://synomare.github.io/notes/` と記事URLを確認します。

記事を削除するときは、管理画面で対象記事を開き、上部（画面幅によってはメニュー内）の **Delete** を選んで確認します。確認すると削除コミットが作成され、Markdownと生成済み記事HTMLが取り除かれて数分後に一覧からも消えます。下書き承認・予約公開は使わず、下書きフラグで安全に公開前確認を行います。

Notes一覧では、タイトル・概要・タグの全文検索、タグ・年の絞り込み、URL共有に対応しています。検索条件を残したURLをブックマークや共有に使えます。

## Worksを管理画面から更新する

1. 管理画面の **Works → New Work** を開きます。
2. slug、作品名、制作年、説明、種別を入力します。
3. 必要に応じてリンク先、一覧画像、表示優先度を設定します。
   - 一覧画像は10MBまで選択できます。大きすぎる画像はアップロード前に縮小してください。
4. すぐ公開しない場合は「公開設定」の下書きをオンにして保存します。公開するときはオフにして **Publish** を押します。
5. **Publish** を押すと `works.html` が自動生成され、数分後に公開されます。
6. 削除するときは対象作品を開き、上部の **Delete** を選びます。

既存作品「嶼群（博物館（たち））」もWorksコレクションへ移行済みです。一覧画像を設定した作品だけ画像付きの行になり、未設定の場合は従来どおりテキスト行で表示されます。

Works一覧では、作品名・説明・種別の全文検索、種別・年の絞り込み、URL共有に対応しています。

### 公開に失敗した場合

- GitHub Actions の `Build and deploy GitHub Pages` が失敗した場合、公開中のサイトは直前の成功版のまま維持されます。
- 原稿の修正は管理画面から行い、再度 Publish します。
- 誤った更新を戻す必要がある場合は、GitHub のコミット履歴から該当ファイルを復元します。OAuth ID、secret、アクセストークンはリポジトリへ保存しません。

## 記事を新規作成する
1. ターミナルでリポジトリ直下に移動します。
2. 次のコマンドで記事を生成します。
   ```
   node scripts/new-post.mjs slug "タイトル" --date=YYYY-MM-DD --summary="概要文" --tags=タグ1,タグ2
   ```
   - `slug` は英小文字・数字・ハイフンのみ。URL は `notes/<slug>.html` になります。
   - `--date` を省略すると当日の日付が入ります。
   - `--summary` は一覧やメタ情報に使われる 1〜2 文です。
   - `--tags` はカンマ区切り、または複数回の `--tag` 指定で追加できます。
3. スクリプトが自動で以下を生成・更新します。
   - `notes/content/<slug>.md`: フロントマター付き Markdown 原稿
   - `notes/posts.json`: 投稿メタデータ（ソート済み）
   - `notes/posts.js`: フロント側で読み込む派生データ
   - `notes/<slug>.html`: テンプレートを元にした記事 HTML
4. 生成された Markdown を編集し、本文やメタ情報を整えます。
5. 編集後は `node scripts/new-post.mjs --rebuild` を実行し、HTML と `posts.js` を最新化します。

## 既存記事の編集
- 通常は管理画面から編集します。ローカル作業が必要な場合は `notes/content/<slug>.md` を編集します。
- 編集後に `node scripts/new-post.mjs --rebuild` を実行すると、HTML と一覧データが最新状態になります。

## 再生成のみ行うとき
- Markdown のみ更新した場合は、次のコマンドで一括再生成できます。
  ```
  node scripts/new-post.mjs --rebuild
  ```

## 検証

```text
npm test
npm run check
```

- `npm test` は一時フォルダ内のfixtureでHTML生成、記事順、画像、YouTube/X埋め込み、不正slug、必須項目、壊れたfrontmatterを検証します。
- `npm run check` は公開原稿とWorks原稿を変更せず、現在のコンテンツ全体を検証します。

## Markdown の埋め込み記法
- 段落中に YouTube のリンク（`youtube.com/watch?v=...` または `youtu.be/...`）だけを置くと、`--rebuild` 時に自動でプレイヤーの iframe に変換されます。
- 同様に X / Twitter のステータス URL だけの段落は埋め込みブロックに変換されます。
- 記事内の最初の画像はサムネイル（`image`）として `posts.json` / `posts.js` に記録されます。

## 参考
- 投稿テンプレートは `notes/post-template.html` にまとまっています。スタイルや構造を変えたいときはテンプレートを編集してから再生成してください。
- `notes/posts.js` にはタグ配列のほか `year` や `yearMonth` などの派生プロパティが含まれているため、アーカイブやフィルタ機能を実装する際に利用できます。
